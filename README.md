# Энергетические проекты — интерактивный прототип

Локальный русскоязычный лендинг на React + TypeScript + Vite. Создан по комплекту `01_PROMPT.txt`–`05_ACCEPTANCE.txt` и данным Excel, приведённым в JSON и карте источников. Публикация не выполнялась.

## Запуск

Требуется Node.js 20.19+ или 22.12+; разработка и сборка проверены на Node.js 24.20.0.

```powershell
cd 'D:\Codex Alt\Сайт Константин А групп'
npm ci
npm run dev -- --port 5174 --strictPort
```

Открыть http://127.0.0.1:5174/. Если сервер уже запущен, повторно запускать его на том же порту не нужно. Сервер слушает только loopback.

```powershell
npm run typecheck
npm test
npm run build
npm run preview -- --port 4173 --strictPort
```

Последняя команда открывает собранную версию на http://127.0.0.1:4173/. Готовая статическая сборка находится в `dist/`; её следует смотреть через HTTP-сервер, а не двойным щелчком по HTML.

## Что реализовано

- Все смысловые блоки брифа: предложение, 6 этапов модели, 5 причин выбора энергетики, 3 направления, единая витрина с одним примером, качественная экономика, 8 процедур контроля, 4 принципа, о компании, 7 FAQ и финальное обращение.
- Два различимых сценария: investor и project_owner. Карточка передаёт `industrial-energy-center` в форму инвестора.
- Нативный модальный `dialog`: блокировка фоновой прокрутки, ограничение фокуса, Escape, закрытие по подложке и возврат к исходной кнопке. Документ согласия открывается в том же диалоге, ввод сохраняется.
- Проверка ФИО, выбранного контакта, согласия и необязательных полей. Состояния initial/editing/validation_error/submitting/demo_success/error, блокировка повторного запроса, отмена ожидающей операции при закрытии. Персональные поля очищаются при успехе и закрытии.
- Мобильное меню и якоря с учётом фактической высоты шапки; видимый фокус и режим reduced-motion.
- Локальная SVG-иллюстрация, явно обозначенная условной схемой. Внешние CDN, изображения, шрифты и API не требуются.
- Три честные заглушки документов; `lang=ru`, метаданные, один H1, `noindex,nofollow`.

## Где редактировать

Единый источник текстов и бизнес-данных — **`src/content/site-content.json`**. Исходный `02_CONTENT.json` оставлен без изменений как входной документ; приложение читает только рабочий JSON в `src/content/`.

| Что изменить | Раздел JSON |
| --- | --- |
| Рабочее название и подтверждённые контакты | `brand` |
| Навигация и первый экран | `navigation`, `hero` |
| Разделы, FAQ, сведения о компании | `sections` |
| Проект, параметры и пояснения | `projects` |
| Формы и ошибки | `forms`, `ui.validation` |
| Документы | `legalPages` |
| Подвал и короткие подписи | `footer`, `ui` |

Служебные provenance/refs не выводятся в интерфейсе. Для добавления реальных карточек понадобится расширить компонент витрины: текущая версия намеренно показывает один пример из брифа. Заполнение контактных полей само по себе не подключает отправку или новые способы связи.

Компоненты страницы находятся в `src/components/Sections.tsx`; форма, диалог и иллюстрация выделены отдельно. Типы — `src/lib/types.ts`, правила проверки — `validation.ts`, заменяемые адаптеры — `leadService.ts` и `analytics.ts`.

## Принятые решения и неизвестные данные

- «Энергетические проекты» — временное имя; логотип, юридическое лицо, домен и контакты не выдуманы. Неполный email из источника не показан.
- 150 млн ₽ — сумма проекта без определения CAPEX/привлечения. 10 лет — срок в примере без дополнительной интерпретации. 30% показаны только в подробностях с исходной оговоркой о периоде и методике. Расчётов выплат нет. Оборудование и денежные потоки не названы оформленным залогом.
- Пустые team/experience/partners/cases/metrics и неизвестные `null` сохранены. Вместо вымышленных доказательств опыта — один компактный блок будущих материалов.
- Экономика и FAQ остаются редакционными черновиками из комплекта. Коммерческие факты независимой проверкой не подтверждались.
- Документы представлены именованными диалогами вместо отдельных маршрутов. Поэтому нет неработающих ссылок `/consent` и не требуется серверный fallback.
- Визуальная система — предложение для прототипа: графит, зелёный, светлые поверхности, системный шрифт с кириллицей. Светлый зелёный используется для приоритетного действия на тёмном фоне.
- JSON дополнен только подписями интерфейса в `ui`; смысл и исходные неопределённости сохранены. Неподтверждённая юридическая заметка Excel не использована в публичных текстах.

## Данные, аналитика и demo

`submitLead(payload)` работает локально, не сохраняет и не отправляет персональные данные. Единственный обычный результат — `demo_success`. UI сообщает: «Демонстрация завершена. Данные не отправлены». Таймер нужен только для проверяемого состояния ожидания.

`trackEvent` хранит события только в памяти вкладки: page_view, cta_click, project_open, form_open, form_error и demo_submit_success. При проекции свойств отбрасываются ФИО, контакт, компания, комментарий и описание проекта. UTM — только пять разрешённых параметров, до 160 символов каждый; произвольная query-строка не копируется. Полный referrer заменён на имя хоста. Чтение буфера для разработки доступно через экспорт `getDemoEvents` модуля аналитики. Console, localStorage, sessionStorage, cookies и внешние счётчики не используются.

Dev-сервер Vite использует локальное соединение для обновления кода; данные формы в него не передаются. В готовой сборке этого соединения нет.

Продуктивного события `lead_submit_success` нет. Для него потребуется подтверждённый ответ настоящего сервера. Встречи и договоры — будущие CRM-статусы.

### Воспроизведение ошибки

В PowerShell перед запуском dev-сервера:

```powershell
$env:VITE_DEMO_MOCK_ERROR_ONCE='true'
npm run dev -- --port 5175 --strictPort
```

Первая валидная отправка каждой открытой формы завершится контролируемой ошибкой; повторная завершит демо с теми же введёнными значениями. В обычном режиме ошибок по случайному принципу нет. Флаг работает только в development и игнорируется production-сборкой. После проверки удалите переменную из текущего PowerShell-сеанса либо откройте новый терминал.

## До публичного запуска

1. Подтвердить бренд, юрлицо, контакты, реквизиты, команду, опыт и права на фотографии.
2. Предоставить реальные проекты; уточнить смысл суммы, срока, показателя доходности, механизм обеспечения и условия участия/выхода. Утвердить FAQ и публичные формулировки.
3. Подготовить и утвердить политику и согласие, модель обработки данных, сроки хранения и юридическую модель деятельности.
4. Реализовать серверную валидацию, защиту от повторов/злоупотреблений и безопасную доставку заявок; секреты хранить на сервере.
5. Согласовать Bitrix/CRM, сущности, поля, маршрутизацию двух типов обращений, ответственных и стадии. Затем подключить выбранные уведомления email/Telegram.
6. Выбрать CMS и роли редакторов, продуктивную аналитику, определения KPI и качественного лида. Связать встречи и договоры с CRM, без вымышленных целевых значений.
7. После отдельного решения настроить домен, HTTPS, хостинг, мониторинг и публикацию; заменить demo-состояния и метаданные по подтверждённым данным. `noindex` не является контролем доступа.

Backend, CMS, CRM, платежи, личный кабинет, рассылки и реклама в прототипе не реализованы.
